A. Direct deferred items
========================

1. [S] Per-session segment count in manage UI sessions table.
   Currently shows '—' as a placeholder. The list_capture_sessions_for_run
   query needs to add: (SELECT COUNT(*) FROM segments WHERE
   capture_session_id = s.id) AS segment_count, and CaptureSession
   TypedDict + frontend rendering need the new field. ~30 min.
   Without it the salvage UI is half-blind — you can't see at a glance
   which session contributed which slice of the run.

2. [S] sections_captured TS type tightening.
   types.ts:163 declares it as `number`, but state_builder.py emits
   `int | None`. Frontend uses `?? 0` so it works at runtime, but the
   contract lies. Change to `number | null`.

3. [M] Playwright crash-and-resume smoke test.
   Scaffolded but skipped at tests/integration/test_multi_session_smoke.py.
   To implement, extend the test_frontend_smoke.py fixture chain to
   support process restart against a shared DB file. Real value: the
   only end-to-end visual proof that recovery surfaces correctly in the
   UI. Python-level crash test (test_crash_recovery.py) covers the data
   layer exhaustively, so this is purely UI confidence.

4. [S] RunPendingError alias migration.
   errors.py has `RunPendingError = DraftPendingError` for wire-format
   preservation. The comment claims Task 14 will migrate call sites,
   but that didn't happen. Either complete the rename across callers
   (mechanical sweep) or drop the comment and accept the alias as
   permanent.

5. [S] "Session" column in segments tab.
   Plan called for it ("see which session captured each segment" for
   the salvage workflow). Skipped during Task 18. The data is already
   on the segment rows (capture_session_id); just needs a column in the
   manage page segments table rendering.

6. [S] _seed_reference_attempts scheduler rebuild logic.
   finalize_run and save_and_finish_run skip rebuild_all_states when
   seeded == 0 (no completed segments). But set_active_capture_run ran,
   so the active reference changed and the scheduler may need to
   rebuild from older attempts anyway. Either always rebuild after
   activation, or document why no-attempts case intentionally preserves
   prior model state.


B. Issues from final review — not blocking, but real
====================================================

7. [M] paused_run_id / recorder.capture_run_id desync risk.
   ReferenceController has two state fields managed by separate methods
   (paused_run_id directly, capture_run_id via recorder). Today they
   stay coherent, but no invariant enforces it. The next refactor that
   touches state transitions is at risk. Either consolidate into a
   single state object or add an _assert_invariants helper used by
   tests.

8. [S] delete_capture_session race during active recording.
   API accepts any session_id. If recorder.current_capture_session_id
   == session_id (i.e., the user is mid-segment in the session being
   deleted), next segment-close will hit a FK violation. Add a guard
   raising the appropriate error. Not exposed in the UI today but the
   API surface is exposed.

9. [S] recover_paused_capture_run silently destroys data.
   When multiple drafts exist for a game, picks newest and
   hard_delete_capture_run on the rest. Defensive but silent. Add a
   logger.warning("Discarding stranded draft %s for game %s") so if
   this fires in the wild we know.

10. [S] NotInReferenceError overloaded.
    Used for both "wrong mode" and "no paused run exists" cases.
    Adding NoPausedRunError clarifies the API and matches the spec's
    original intent. Mechanical change.

11. [S] save_and_finish_run atomicity uses raw SQL (Option B).
    Works correctly. Cleaner long-term API would be teaching the mixin
    methods to honor an open transaction (Option A). Defer until you
    have another transaction-spanning operation that needs the same
    pattern.


C. Pre-existing bugs surfaced by this work
==========================================

12. [M] clean_tail_ms is always equal to time_ms for segments with
    deaths.
    Recorder uses _last_spawn_ms which is only set when
    handle_spawn_timing(timestamp_ms=...) gets a non-None value, but
    reference.py:425 calls it with None. So the deaths-tracking
    clean-tail feature has been broken in main since whenever it
    landed. The new recorded_segment_times table now propagates this
    wrong value into attempts. Fix: investigate where timestamp_ms on
    SpawnEvent should come from (Lua-side?) and wire it through.

13. [M] Eight pre-existing pyright errors.
    None new from this work but worth a sweep:
      - cold_fill.py: str | None for state_path
      - recorder.py x2: str passed where EndpointType expected
      - reference.py: str | None for state_path in fill-gap
      - kalman.py x4: EstimatorState attribute access
    Each is small in isolation; one focused PR could clean them all.


D. Test gaps
============

14. [M] Long-run / load test.
    The whole point of this spec was a 50-hour run. No test exercises
    >100 segments or multi-GB accumulation. A test that simulates 1000
    segments across 20 sessions, then runs recovery, would catch
    scaling regressions early.

15. [S] Frontend click-handler tests.
    Vitest covers render but not the new btn-resume / btn-save-and-
    finish / btn-discard-run handlers. Quick add: mock fetch, click
    button, assert URL + body shape.

16. [M] Mutation-test-worthy assertions.
    Some new tests would not catch silent regressions. Example:
    test_save_and_finish_seeds_attempts_and_finalizes does not fail
    if you delete the set_active_capture_run call. One pass: for each
    new test, ask "would this fail if I deleted line X of the
    implementation?".

17. [S] End-to-end real-flow integration test.
    Scenario: user has paused run A, replays a different reference B,
    replay finishes, recovery on next restart still picks A back up.
    Was unit-tested but not integration-tested. The interaction of
    `id NOT LIKE 'replay_%'` filter + replay's lifecycle is fragile
    and a place where future-Claude could easily break recovery.

18. [S] Unused imports cleanup.
    pytest_asyncio unused in test_crash_recovery.py and
    test_multi_session.py. Trivial ruff sweep.


E. Architecture improvements
============================

19. [L] Replace _init_schema rebuild-on-mismatch with real migrations.
    db/core.py:158-181 drops tables when columns drift. Greenfield-
    friendly today; catastrophic once you've accumulated reference
    runs you care about. Move to alembic or a homegrown forward-only
    migration log BEFORE the data starts mattering. This is the single
    biggest tech debt item — it's a future "I lost my data" event
    waiting to happen.

20. [M] Verbal overload of "session" across the codebase.
    Three meanings now: sessions table (practice), attempts.session_id
    (polymorphic parent), capture_sessions (recording sessions within
    a run). Renaming attempts.session_id → attempts.parent_id reflects
    its actual semantics. Mechanical sweep, no migration needed
    (greenfield).

21. [M] is_primary auto-promotion on segment delete.
    Spec deferred this. Today: deleting the primary segment for a
    geography silently drops it from practice scheduling. Now that
    segments carry capture_session_id, the natural behavior is to
    auto-promote the most-recent active sibling. Decide if you want
    this once you've used delete-segment in anger.

22. [M] recorder._close_segment ordinal is O(n).
    Today: SELECT COUNT(*) FROM segments WHERE reference_id = ? per
    close. With many segments this is O(n²) over a full run. Track
    in-memory per session — ordinal isn't load-bearing for correctness,
    only for display ordering, so a slight desync after crash is
    acceptable.

23. [M] Replay-creates-ephemeral-capture_run is awkward.
    Replay needs a capture_run row purely so the recorder has somewhere
    to attach segments. The id LIKE 'replay_%' filter in recovery is
    a hack working around it. Cleaner: scratch run that's not in
    capture_runs at all. Big refactor, low priority — the hack works.

24. [S] One-paused-run-per-game as a DB constraint.
    Currently enforced only in code via recover_paused_capture_run's
    delete-older behavior. Belt + suspenders: a partial unique index
    `WHERE draft = 1 AND id NOT LIKE 'replay_%'`.


F. Efficiency improvements
==========================

25. [S] get_paused_state runs 2 DB queries on every SSE event.
    Called from the state builder, fires on every TCP event. For
    high-event-rate flows (rapid segment closes, deaths, etc.) this is
    real overhead. Cache the result and invalidate only on lifecycle
    transitions, or fold both queries into one.

26. [S] _compute_is_primary runs a query per segment close.
    N segments per session = N queries. Could batch at session-end:
    one query that updates all segments captured in this session,
    marking the ones whose geography has no other primary. Or
    precompute primary-by-geography at start of session.

27. [M] Spinrec file accumulation.
    Discarded runs clean up. Finalized runs do not — spinrecs
    accumulate forever in data/<game>/rec/. After many references this
    grows. Add a per-reference "delete spinrec" action, or an automatic
    sweep ("references older than N months without practice activity").
    Probably matters at the 1+ year mark.

28. [S] recover_paused_capture_run N+1 on draft cleanup.
    When multiple stranded drafts exist, hard_delete_capture_run is
    called per row. Bulk delete possible but rarely matters (multiple
    drafts is the failure case, not the norm).


G. UX polish
============

29. [S] "Session N of M" indicator during recording.
    During a long multi-session run, the user may forget which session
    they're in. The recording panel could show
    "Recording — Session 3 — N segments captured this run".

30. [M] Save & Finish dialog UX.
    Currently inline <input> near the buttons. A modal "Name this run"
    prompt on Save & Finish click is more deliberate, matches typical
    save-dialog convention, and prevents accidental saves with the
    default placeholder name.

31. [S] Visual differentiation of paused vs recording.
    Both states use similar styling today. A clearer visual cue —
    "paused" color/icon vs "active" color — helps the user instantly
    know what state they're in.

32. [S] Per-segment delete confirmation message.
    Already has confirm but it's generic. Including segment description
    + capture time in the prompt makes it less ambiguous what's being
    deleted.

33. [S] Empty-state messaging.
    Verify the manage page reads well with zero references and no
    paused run after the rework. Easy to break first-run UX during a
    refactor and not notice.


H. Operational / observability
==============================

34. [S] Session-end summary log.
    When _end_current_session fires, log "session X (ordinal N) ended
    after T minutes, captured K segments, reason=<reason>". Aids
    future debugging when something feels off.

35. [M] Recovery audit trail.
    recover_paused_capture_run makes silent decisions: kept this run,
    deleted that one, marked these orphan sessions crashed. A small
    recovery_log table, or even structured logger calls, would help
    diagnose the rare "wait, where did my run go?" cases.

36. [S] Spinrec file unlink failures swallowed.
    hard_delete_capture_run and delete_capture_session use `pass` on
    OSError. Log it — disk-full or permissions errors are exactly the
    kind of thing you want surfaced.
