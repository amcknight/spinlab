B. Issues from final review — not blocking, but real
====================================================

7. [M] paused_run_id / recorder.capture_run_id desync risk.
   ReferenceController has two state fields managed by separate methods
   (paused_run_id directly, capture_run_id via recorder). Today they
   stay coherent, but no invariant enforces it. The next refactor that
   touches state transitions is at risk. Either consolidate into a
   single state object or add an _assert_invariants helper used by
   tests.

11. [S] save_and_finish_run atomicity uses raw SQL (Option B).
    Works correctly. Cleaner long-term API would be teaching the mixin
    methods to honor an open transaction (Option A). Defer until you
    have another transaction-spanning operation that needs the same
    pattern.

D. Test gaps
============

14. [M] Long-run / load test.
    The whole point of this spec was a 50-hour run. No test exercises
    >100 segments or multi-GB accumulation. A test that simulates 1000
    segments across 20 sessions, then runs recovery, would catch
    scaling regressions early.

16. [M] Mutation-test-worthy assertions.
    Some new tests would not catch silent regressions. Example:
    test_save_and_finish_seeds_attempts_and_finalizes does not fail
    if you delete the set_active_capture_run call. One pass: for each
    new test, ask "would this fail if I deleted line X of the
    implementation?".

18. [S] Unused imports cleanup.
    pytest_asyncio unused in test_crash_recovery.py and
    test_multi_session.py. Trivial ruff sweep.


E. Architecture improvements
============================

19. [L] Replace _init_schema rebuild-on-mismatch with real migrations.
    db/core.py:158-181 drops tables when columns drift. Greenfield-
    friendly today; catastrophic once you've accumulated reference
    runs you care about. Move to alembic or a homegrown forward-only
    migration log BEFORE the data starts mattering. This is the single
    biggest tech debt item — it's a future "I lost my data" event
    waiting to happen.

21. [M] is_primary auto-promotion on segment delete.
    Spec deferred this. Today: deleting the primary segment for a
    geography silently drops it from practice scheduling. Now that
    segments carry capture_session_id, the natural behavior is to
    auto-promote the most-recent active sibling. Decide if you want
    this once you've used delete-segment in anger.

22. [M] recorder._close_segment ordinal is O(n).
    Today: SELECT COUNT(*) FROM segments WHERE reference_id = ? per
    close. With many segments this is O(n²) over a full run. Track
    in-memory per session — ordinal isn't load-bearing for correctness,
    only for display ordering, so a slight desync after crash is
    acceptable.

23. [M] Replay-creates-ephemeral-capture_run is awkward.
    Replay needs a capture_run row purely so the recorder has somewhere
    to attach segments. The id LIKE 'replay_%' filter in recovery is
    a hack working around it. Cleaner: scratch run that's not in
    capture_runs at all. Big refactor, low priority — the hack works.


F. Efficiency improvements
==========================

25. [S] get_paused_state runs 2 DB queries on every SSE event.
    Called from the state builder, fires on every TCP event. For
    high-event-rate flows (rapid segment closes, deaths, etc.) this is
    real overhead. Cache the result and invalidate only on lifecycle
    transitions, or fold both queries into one.

26. [S] _compute_is_primary runs a query per segment close.
    N segments per session = N queries. Could batch at session-end:
    one query that updates all segments captured in this session,
    marking the ones whose geography has no other primary. Or
    precompute primary-by-geography at start of session.

27. [M] Spinrec file accumulation.
    Discarded runs clean up. Finalized runs do not — spinrecs
    accumulate forever in data/<game>/rec/. After many references this
    grows. Add a per-reference "delete spinrec" action, or an automatic
    sweep ("references older than N months without practice activity").
    Probably matters at the 1+ year mark.

28. [S] recover_paused_capture_run N+1 on draft cleanup.
    When multiple stranded drafts exist, hard_delete_capture_run is
    called per row. Bulk delete possible but rarely matters (multiple
    drafts is the failure case, not the norm).


G. UX polish
============

29. [S] "Session N of M" indicator during recording.
    During a long multi-session run, the user may forget which session
    they're in. The recording panel could show
    "Recording — Session 3 — N segments captured this run".

30. [M] Save & Finish dialog UX.
    Currently inline <input> near the buttons. A modal "Name this run"
    prompt on Save & Finish click is more deliberate, matches typical
    save-dialog convention, and prevents accidental saves with the
    default placeholder name.

31. [S] Visual differentiation of paused vs recording.
    Both states use similar styling today. A clearer visual cue —
    "paused" color/icon vs "active" color — helps the user instantly
    know what state they're in.

32. [S] Per-segment delete confirmation message.
    Already has confirm but it's generic. Including segment description
    + capture time in the prompt makes it less ambiguous what's being
    deleted.

33. [S] Empty-state messaging.
    Verify the manage page reads well with zero references and no
    paused run after the rework. Easy to break first-run UX during a
    refactor and not notice. (Manual UI pass deferred to user from
    followups Task 7.)
