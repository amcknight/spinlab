## Patterns observed by lenses

- **Architect**: PracticeSession and SpeedRunSession evolved independently with near-identical lifecycle (start/stop/done-callback). The deeper asymmetry (scheduler vs queue, estimator pass vs direct DB) is intentional, but the done-callbacks are pure DRY candidates.
- **Control-inversion**: Callback-heavy dependency flow (lambdas passed to subordinates) hides the dependency graph from static analysis. Private methods called from routes (_clear_ref_and_idle, _handle_attempt_invalidated) blur the public API boundary.
- **Test-skeptic**: async sleep for synchronization is pervasive across test_practice.py and test_practice_coverage.py. Mock-only route tests cluster in test_dashboard_references.py — shallow verification.
- **Dead-code**: Codebase is in very good hygiene shape post-cleanup. Only one real find: unused `cmd` parameter in `_process_result` from incomplete condition-tracking work.
- **Types**: Event dispatch passes `event: object` through multiple layers and relies on isinstance checks. No `ConditionMap` type anchor existed — conditions flowed as ad-hoc `dict[str, str | bool]` through 4+ files.
- **Observability**: Scheduler estimator loops (process_attempt, rebuild_all_states) had no try/except adding segment/estimator context. Six observability gaps were already addressed by CF3 in the prior session.
