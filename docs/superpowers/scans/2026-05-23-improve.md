## Patterns observed by lenses

(Verbatim from each lens's "## Patterns I noticed" section, archival only.)

### Architect
1. Routes as state-mutation gateways instead of command translators.
2. Encapsulation boundaries erode through public fields (ReferenceController exposes `recorder`, `paused_run_id`, `condition_registry`).
3. Asymmetric event-handling paths (Practice via `receive_result()`, HyperPlay via queue).
4. Implicit dependencies on capture-domain internals (death penalty, condition definitions, replay totals).

### Control inversion
1. Lazy initialization vs. ownership (Scheduler dual-owned by SessionManager + PracticeSession).
2. State pulling during event dispatch (handlers pull game_id/mode/session_id from manager instead of receiving from event).
3. Callbacks over event buses (timing modules + controllers use callback functions).
4. Per-module state machines with shared conditions (detector's `_finish_emitted`, `_cp_acquired`, `_exit_this_frame` scattered).
5. Eager construction vs. deferred errors (HyperPlaySession, ReferenceController, ColdFillController validate at init).

### Test skeptic
1. Healthy blend of mocking strategies (MagicMock for stubs, FakeEmuBackend for behavior, real DB for schema).
2. Event-driven tests are well-structured (detector/transition/practice drive state through synthetic snapshots).
3. Capture tests (new event-level recording) use real Database + FakeEmuBackend, avoid over-mocking.
4. Private state assertions in detector are acceptable (pure state machine).
5. Timing-sensitive test anti-pattern is rare but present (hyper_play + practice).
6. Estimator sanity tests parametrize well.
7. Routes/API tests are thin (acceptable — FastAPI's responsibility).

### Dead code
1. Recent major refactors were very thorough (event-level recording cleanup).
2. Dead code is cleaned up promptly (no leftover helpers).
3. Comments are generally honest (preserve historical context).
4. Cascade logic is well-documented (one docstring miss).

### Types
1. Enum-shaped data as bare strings at layer boundaries (`EndpointType` → `str` → `dict[str, str]`).
2. TypedDict used for DB rows but not for dataclass method returns (`to_dict` returns bare `dict`).
3. No removal candidates (every typed abstraction is load-bearing).

### Observability
1. Retry-then-fail asymmetry (only final-retry logged).
2. Silent fallback over sentinel values (`pick_next()` → None without "why").
3. Per-frame exception suppression with flags (logs first failure then silent).
4. Buffered-then-flushed events lose causality (SegmentRecorder in-memory buffer).
5. Nullable outputs without "why" (`ModelOutput.total.expected_ms = None`).
6. State transitions without entry/exit markers (`_finish_emitted` set/clear silent).
