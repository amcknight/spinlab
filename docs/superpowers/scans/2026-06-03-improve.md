## Patterns observed by lenses

**Lens 1 (Architect):** Dependency injection inconsistent — SessionManager lazy-creates, ReferenceController is injected, PracticeSession constructs own. ConditionRegistry uniquely uses replace-after-construction. Async/sync boundary is clean.

**Lens 2 (Control-inversion):** Two architectural rifts — (a) SessionManager has well-formed `start_practice/start_reference` entry points, but routes sometimes bypass them and mutate directly (suggests public API incomplete); (b) snapshot-pattern for volatile reads is recognized in StateBuilder's docstring but not enforced by a factory accessor on ReferenceController.

**Lens 3 (Test-skeptic):** Recent tests stub realistic paths and stay below gates; no end-to-end coverage of "practice start → baseline captured → live diff → stop → baseline cleared". Formula assertions in `estimators/test_live_view.py` (e.g. `expected_episode_diff_ms == approx(expected_ms - 20_000.0)`) are excellent.

**Lens 4 (Dead-code):** Codebase clean. Recent live-view overhaul deleted orphaned code (`renderPracticeInsight`, legacy DOM nodes) thoroughly. Only documented duplicate is `_running_min_clean_for_route` with an explicit "consolidate later" comment.

**Lens 5 (Types):** Pattern of `Sequence[Mapping[str, Any]]` standing in for `Sequence[AttemptRow]` across 6+ sites. Policy/objective callbacks treat ctx as bare dict — open-callback idiom but TypedDict for known fields would help discoverability.

**Lens 6 (Observability):** Logging level discipline is good (`log.info`/`log.warn` wrappers structure context). But session snapshot path has zero logging — operational gap on a critical-now path. Async task exception handling is via done callbacks; synchronous-after-task-fire snapshot escapes that net.
